# 028 — Commerce: checkout UI, orders, fulfilment and emails

**Status:** approved 2026-11-23 · **Agent:** frontend-engineer (+ backend part) · **Branch:** `feat/028-commerce-orders` · **Needs:** 026 and 027 merged

## Scope
- **Checkout flow:** the cart's "Checkout" calls 027 and redirects to Stripe; 409 problems are shown on the cart
  lines. The success page `/shop/order/success?session_id=…` polls the status until the order is paid, then shows it
  and clears the cart; cancel returns to the cart.
- **Orders for buyers:** "My orders" (app layout, logged in) and the **guest order page** `/orders/<token>` (no login,
  `noindex`): lines, status, shipping address and tracking, booking times (store time and local time).
- **Digital delivery (backend + UI):** a download button per digital line → a short-lived signed URL (006 pattern),
  only for `paid` / `fulfilled` orders; a per-line download limit (`ORDER_DOWNLOAD_LIMIT`, default 5); nothing after a
  refund.
- **Bookings:** booking details on the order and an `.ics` calendar file generated by the backend (plain text, no
  dependency).
- **Admin orders screen:** list with filters (status, type, date, search by number or email), order detail, **mark
  shipped** (carrier + tracking number) and **mark fulfilled**, an attendee list per service slot. Refunds stay in
  Stripe (link to the payment in the Stripe dashboard).
- **Emails** (existing email pipeline + react-email templates): order confirmation with the order link (the token
  link for guests) and a shipped notice with tracking, sent from the `order_paid` / shipped events. A failed send is
  logged and never breaks the webhook.
- Docs: ARCHITECTURE "Commerce" section, housekeeping commands, deploy-vercel Stripe steps if 027 didn't add them.
- Playwright `tests/commerce-orders.spec.ts`: checkout with Stripe **faked at the API boundary** (a fake payments
  backend selected by an env var in local/CI runs — never real Stripe in CI), success page, guest order page via the
  token, download allowed then limited, admin marks shipped, a refund event turns downloads off.

## Out of scope
Tax, coupons, refunds from our admin, linking earlier guest orders to a new account (later), invoices / PDF.

## New dependencies
None.
